Iconos públicos · r01

kiwi · wireframe F2 · kit gris · iconos solo Lucide: los de la librería salen de design/lab/lucide-icons.js y los «de la aplicación» se importan de verdad de lucide-static (node_modules del repo).

Prototipo de estructura y uso: un GIcon simulado en JS con la API propuesta (name, label, filled, flip-rtl) y un registro por aplicación (createIcons([...])). Los avisos de desarrollo se muestran en el panel del final (en la librería irían a console.warn); así la consola queda limpia. Se sirve por HTTP desde la raíz del repo (los módulos ES no cargan con file://).

1. Lo que trae la librería: público por nombre

Los … iconos de la lista library de packages/vue/scripts/icons.json (los que usan los componentes) ya van en el paquete. Con GIcon público, la aplicación los usa por nombre sin registrar nada y sin coste extra. La lista pasa a ser API: puede crecer; quitar uno es un cambio mayor.

2. Decorativo o con nombre

Por defecto, decorativo (aria-hidden): el significado lo lleva el texto de al lado. Con label, el icono es la única fuente del significado y entra al árbol como imagen con nombre (role="img" + aria-label). Nunca es enfocable; si hay que pulsarlo, es un GBtn icon con aria-label en el botón.

3. En un botón

Sin props nuevas en GBtn: el icono va en el slot (prepend, append, o el contenido con icon). El hueco ya es aria-hidden y fija el tamaño. La prop icon de GBtn sigue siendo Boolean (modo solo icono).

Con texto 
<GBtn>
  <template #prepend><GIcon name="lock-open" /></template>
  Permitir edición
</GBtn>
Solo icono: el nombre lo pone el botón, el icono sigue decorativo 
<GBtn icon aria-label="Desbloquear">
  <GIcon name="lock-open" />
</GBtn>
Dirección en RTL: flip-rtl solo en iconos que indican «adelante/atrás»

La marca de verificación no se espeja: espejar es decisión de quien elige el icono, no automática.

Uso indebido (aviso de desarrollo): label dentro de un hueco aria-hidden 
<GBtn>
  <template #prepend><GIcon name="lock-open" label="Desbloquear" /></template>
  Permitir edición
</GBtn>

El nombre se pierde (el hueco lo oculta). El aviso lo detecta con closest('[aria-hidden="true"]') al montar.

5. En una sección (tokens.md §23.6)

6. Items como datos: icon con un nombre

En GTabs, GMenu y GSidebar, hoy el campo icon de un item solo se pasa al slot icon: sin slot no se dibuja nada. Propuesta: si no hay slot y icon es una cadena, el componente dibuja <GIcon :name="item.icon" />. El slot, si existe, sigue mandando.

const items = [
  { id: 'fotos', label: 'Fotos', icon: 'image' },
  { id: 'ubic', label: 'Ubicación', icon: 'map-pin' },
  { id: 'video', label: 'Video', icon: 'play' },
  { id: 'perm', label: 'Permisos', icon: 'lock-open' },
  { id: 'notas', label: 'Notas' }   // sin icono: solo etiqueta
]
<GTabs v-model="tab" :items="items" />   // sin slot icon

    7. Registro de un icono propio (lo que Grana no incluye)

    La aplicación importa los iconos de lucide-static (cadenas SVG, un módulo por icono: el empaquetador solo lleva los importados) y los registra una vez al crear la app. El nombre no se escribe: sale de la marca class="lucide lucide-<nombre>" que trae cada cadena (también de los alias: Unlock es lock-open). Solo se aceptan elementos de dibujo de Lucide; todo lo demás se rechaza.

    // main.js
import { createApp } from 'vue'
import Grana, { createIcons } from '@grana/vue'
import { LockOpen, MapPin, Image, Play } from 'lucide-static'

createApp(App)
  .use(Grana)
  .use(createIcons([LockOpen, MapPin, Image, Play]))   // o app.use(Grana, { icons: [...] })
  .mount('#app')
